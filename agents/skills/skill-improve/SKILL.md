# Skill Improve

## 工作流

按下面的顺序逐项优化目标 Skill 的 `SKILL.md`，直接修改：

1. **Explain the why**：如今的大模型本身具备很强的理解能力和推理能力；只要给出合理的约束框架，它就不会机械执行指令，而是真正落地达成目标。因此对于每一条给到模型的要求，尽量说明为什么要这么做，目的是什么。但不要为常识性规则添加空泛解释。
2. **keep it clean**。删掉会引发无效工作或无实际作用的内容。具体就是：删除不会改变模型执行方式、关键决策、异常处理或产出质量的铺垫、常识说明、重复示例、低价值检查项和边界穷举。
3. **审查章节结构**：先列出每个章节承担的作用，检查章节之间是否职责重叠；将重复的目标、流程、验证要求和完成标准合并到最合适的位置，删除没有独立作用的章节。
4. **保留必要明确性**：能够减少模型判断的固定文件、输入字段、条件、状态、禁止事项和验收标准应明确列出。
5. **精炼局部表达**：如果 2 句话表达同一个意思，那能用一句话就不用 2 句话表达，能用 10 个字就不用 30 个字表达。但不要强制把多个意思压缩成一句话。
6. **删除迭代痕迹**：只写当前有效规则和动作，不写历史纠错、旧版对比或自我提醒； 
7. **最终检查**：重新阅读整份 Skill，确认不存在重复章节、重复约束、过长主流程或本应按需加载的细节；`SKILL.md` 不超过 500 行。

## 最终输出格式和质量要求

### 输出格式

优化后的目标 Skill，主文件为 `<目标 Skill 根目录>/SKILL.md`。

### 质量要求

- 上述 8 项优化全部执行到位。
- 不存在重复章节、重复约束、过长主流程和本应按需加载的细节。
- 不存在错别字、TODO、占位内容和不会被使用的文件。
- `SKILL.md` 不超过 500 行。

## 注意事项

- 不得在未读取目标 `SKILL.md` 的情况下开始优化。
- 只优化表达、结构和冗余内容，不改变 Skill 的既定目标、业务语义和约束，也不新增未经用户确认的要求。
- 禁止做隐藏性假设。
- 优化已有 Skill 时，只处理与优化直接相关的内容，不改变无关的现有行为。
