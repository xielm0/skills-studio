# good skill 标准

作为一个good skill，主要是要做好以下几个事情

1. 说清楚 目标 
2. 说明白 怎么去做， 也就是有具体的工作流程，形式类似SOP的工作流
3. 明确 输出的质量要求
4. 明确 过程中的行为要求。 
5. 文字表达 要准确和简洁。

质量要求和约束的区别，质量要求针对的是产物，约束针对的是行为。 

## 说清楚 目标

skill的目标能用一句话说清楚。


## 清晰的工作流

- 工作流要完整：工作流要覆盖完成任务目标所必需的关键步骤和分支。
- 每个步骤都清晰的说明他的输入和输出。现在的AI都已经足够的聪明，相比告诉他要怎么去做，更重要的是告诉他这个步骤的目标和输出是什么。
- 步骤指令清晰：每个步骤都能清晰的说明要做的事情，包含必要的判断和异常处理。如果还清晰的告诉AI怎么去做，则更好。  


## 明确输出和质量要求

Skill 必须明确说明最终输出是什么什么和质量要求。 

- 质量要求必须针对产物，而不是中间行为。中间行为的要求属于约束。
- 质量要求必须是可检查，可判断，常用于输出前自建。

## 明确约束

针对AI的行为进行约束，也就是要求AI一定要做什么和禁止做什么，还可以引入应该做什么。

约束分must、must not 和 should.
- 一个good skill一定会有 must 和 must not，否则就不算一个good skill
- 但must 和 must not 不一定需要单独章节，可以在工作流或其他段落中有体现。

示例：
- 大纲must要用户确认后才进入下一步。
- 禁止AI做自动隐藏性假设。


## 文字表达

1. **无低价值内容**：无引发无效工作或无实际作用的内容。不存在不会改变执行方式、关键决策、异常处理或产出质量的铺垫、常识说明、低价值检查项和边界穷举。
2. **无迭代痕迹**：skill中只写当前有效规则和动作，不写历史纠错、旧版对比或自我提醒； 
3. **表达精炼**：每个要点只表达一个独立意思，没有同义复述和无行动价值的补充。
4. **篇幅受控**：`SKILL.md` 不超过 500 行，但不能仅凭未超过行数上限判断其表达简洁。
5. **Explain the why**：因为现在模型很聪明，Explain the why 比罗列规则更重要，所以Explain the why 是有必要的，不属于表达不简洁
